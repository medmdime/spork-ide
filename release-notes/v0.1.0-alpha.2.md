This is an alpha: an early build of both apps, not signed, with rough edges and missing pieces. Try it on projects
you have a copy of, and expect bugs.

## What's new since alpha 1

**Java projects open on their own.** A folder with one build tool (Maven or Gradle) at its root is loaded as soon as
it opens; with both, a notification asks which to load.

**JDKs and language levels.**

- Download JDK…: pick a version and a vendor (Temurin, Zulu, Corretto, Oracle OpenJDK and others); the archive's
  checksum is verified before it is unpacked. It is offered by the "Project JDK is not defined" banner, Project
  Structure and a run configuration's JRE field.
- Project Structure (⌘;): the project's SDK and language level, each module's, and the list of SDKs.
- Changing a language level writes it to `pom.xml` or `build.gradle(.kts)`, and the editor's errors follow; Alt+Enter
  on a "feature not available at this level" error offers to raise it.
- JDKs are found where SDKMAN, Gradle, mise, asdf and jabba put them.

**Kotlin.**

- Kotlin in Gradle (Kotlin and Groovy scripts) and Maven projects, alone or mixed with Java: errors, completion, the
  source and test folders. The Kotlin language server is downloaded on first use, under its own licence, and
  replaced by the newest build when one expires.
- Run `main` from the gutter through Gradle or Maven, a Kotlin run configuration, and debugging: breakpoints in
  lambdas, top-level functions and Java classes, stepping into Java, Kotlin expressions in watches.
- New ▸ Kotlin Class/File.

**Spring Boot.**

- A Spring Boot project gets a Spring Boot run configuration for each application when it is loaded (a setting turns
  this off), with active profiles and overridden properties.
- Services shows the application starting and then a link to its port; the Actuator tab shows its beans, health,
  mappings and environment.
- `application.properties` and `application.yml`: completion, documentation, validation, and Go to Declaration into
  your `@ConfigurationProperties` classes. The Spring Boot language server runs on Java 21; when you have none, one is
  downloaded for it alone.

**Java debugging.**

- Stepping with filters, Force Step Into (⌥⇧F7) into JDK classes, frames and values written the familiar way, library
  frames folded.
- Breakpoints that log an expression, exception breakpoints (any exception, caught or uncaught), the prompt when a
  condition fails.
- The program in its own terminal with input; Pause Program; a thread chooser, Copy Stack, Reset Frame.
- Reload Changed Classes after a build; Remote JVM Debug, Attach to Process and JUnit 4 configurations; values shown
  inline while stopped.

**Fixes.**

- The Java debugger's server now listens on this computer only (127.0.0.1); before, it listened on every network
  interface.
- Windows and Linux builds: Spork builds without Unix-only code, and the IDE's menus leave out what Windows doesn't
  have.
- Spork.app now reports the release's version.

Not yet: signed apps, installers and updates; Kotlin test runs; Spring Boot's Update Running Application and the
Initializr wizard; method breakpoints and JUnit 5.

## Opening the unsigned apps

**macOS.** Unzip and move the app to Applications. The first time, macOS refuses to open it: open System Settings ›
Privacy & Security and click Open Anyway beside the app's name, or run
`xattr -dr com.apple.quarantine "/Applications/Spork IDE.app"` (or `/Applications/Spork.app`) in a terminal.

**Windows.** Unzip, then start `Spork IDE\Spork IDE.exe` or `Spork\spork.exe`. When SmartScreen says "Windows
protected your PC", click More info › Run anyway. `Spork IDE\bin\spork-ide.exe` opens folders from a terminal.

**Linux.** Extract into `~/.local`, which puts the apps in `~/.local/bin` and their menu entries in
`~/.local/share/applications`:

```bash
tar -xzf Spork-IDE-v0.1.0-alpha.2-linux-x64.tar.gz --strip-components=1 -C ~/.local
tar -xzf Spork-v0.1.0-alpha.2-linux-x64.tar.gz --strip-components=1 -C ~/.local
```

The apps draw with Vulkan and need its driver, and the Wayland or X11, xkbcommon, fontconfig and ALSA libraries. On
Ubuntu 24.04 or newer:

```bash
sudo apt install git libvulkan1 mesa-vulkan-drivers libxkbcommon-x11-0 libwayland-client0 libx11-xcb1 libfontconfig1 libasound2t64
```
