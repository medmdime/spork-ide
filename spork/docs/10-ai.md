# AI features

Fork ships two AI features (Generate Commit Message, Code Review) with editable prompts ("Edit AI Request… / Reset to Default").
Spork matches those and adds more, under three rules:

1. **Off by default; bring your own provider.** Nothing leaves the machine until the user configures a provider.
2. **Preview before send, preview before act.** The user can see exactly what is sent (diff size, files); AI never runs a git command
   by itself: it proposes, the user clicks the normal op.
3. **Local-first option.** Ollama / any OpenAI-compatible local server works with the same features.

## 1. Providers (`spork_ai`)
```rust
pub trait Provider { async fn complete(&self, req: AiRequest, sink: impl FnMut(&str)) -> Result<AiResponse>; }
```
Implementations: Anthropic Messages API, OpenAI-compatible Chat Completions (covers OpenAI, OpenRouter, Ollama, LM Studio, vLLM, Azure), all over `ureq` (crate `spork_ai`); streaming (SSE) comes later.
Config: provider · model (free text with suggestions, e.g. `claude-sonnet-5-5` / `claude-haiku-5-5` for fast commit messages) · endpoint · key (keyring) · max input tokens · timeout.
Prompts: stored as editable templates in settings, with `Reset to default`; variables `{diff}`, `{files}`, `{branch}`, `{recent_subjects}`, `{conventions}`.

## 2. Data limits & privacy
- Exclude globs (default: lockfiles, `*.min.js`, `*.map`, binaries, `.env*`, `*.pem`, `*.key`, LFS pointers).
- Secret scan before sending (regex pack for common keys/tokens); on hit → block with "remove or send anyway".
- Diff truncation strategy: per-file cap, then summary of omitted files (name + +/− counts).
- "What will be sent" expandable panel before every request; per-repo opt-out (`.git/spork/ui.json`) and a shared opt-out (`.spork/ai.json: {"enabled": false}`) for companies.

## 3. Features (priority order for P6)
| # | Feature | Where | Input → Output |
|---|---|---|---|
| 1 | **Commit message** | ✦ button in commit box (M07) | staged diff + recent subjects (style matching) + optional Conventional Commits → subject + body, streamed into the fields, editable |
| 2 | **Code review** | commit / range / working copy context menu | diff → Markdown review in a side panel (`TextView`); findings link to `file:line` and open in the diff |
| 3 | **PR description** | Create PR (M15) | branch commits + diff stat → title + body |
| 4 | **Conflict resolution suggestion** | per conflict in the 3-way merger (M11 §4) | base/local/remote chunk + surrounding code → proposed merged text shown as a 4th option "Take suggestion"; never auto-applied |
| 5 | **Explain** | commit details / blame line / file history | commit(s) + diff → plain explanation ("why did this line change?") |
| 6 | **Interactive rebase planner** | interactive rebase dialog (M11 §3) | commit list → suggested squash/fixup grouping + reworded messages, applied to the todo only after user accepts |
| 7 | Branch name suggestion | Create branch | staged diff or issue title → `feature/…` |
| 8 | Release notes | tag range context menu | commits between tags → Markdown changelog grouped by type |
| 9 | "Ask Git" palette | `Cmd-Shift-P` → "Ask…" | natural language ("undo my last commit but keep changes") → proposed op from the Spork op registry with its parameters, shown as the normal dialog prefilled. Never raw shell. |
| 10 | Semantic history search (later) | Search tab | local embeddings index of commit messages + diffs (opt-in, local model only) |

## 4. UX details
Streaming output with Stop button; cost/token estimate shown for hosted providers; results cached per (diff hash, prompt hash) so re-opening a review is free; errors shown inline, never block git work.

## 5. Tests
Provider mocks with recorded SSE streams; prompt-template rendering snapshots; secret-scan unit tests; "Ask Git" maps a fixed list of 50 phrasings to the expected op + params (eval run nightly against the configured model, not in PR CI).
