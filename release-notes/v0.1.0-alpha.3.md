This is an alpha: an early build of both apps, not signed, with rough edges and missing pieces. Try it on projects
you have a copy of, and expect bugs.

## What's new since alpha 2

**Running tests.**

- Run icons in the gutter on JUnit 4, JUnit 5 and TestNG test classes and methods, in Java and Kotlin, with Run,
  Debug and Modify Run Configuration…; after a run each test shows whether it passed or failed.
- JUnit and TestNG run configurations (all in package, pattern, class, method); a run from the gutter or the Project
  view makes a temporary one, which Save Configuration keeps.
- The test tree in the Run tool window: each test's state and duration, the totals, Rerun, Rerun Failed Tests, Show
  Passed, Show Ignored, sorting, previous and next failure, export; a selected test's output, links from stack traces
  to the source, and "Click to see difference" for a failed comparison.
- Gradle projects run their tests with Gradle, Maven projects with Spork IDE's own runner; debugging a test stops at
  its breakpoints, in Java and Kotlin.

**Spring Boot.**

- Update Running Application (⌘F10), with the configuration's On 'Update' action and On frame deactivation choices:
  classes are reloaded in a debug session, or the application restarts through DevTools.
- New Project › Spring Boot: the project wizard on start.spring.io, which creates the project and opens it.
- The Endpoints tool window, and gutter icons on request mappings (open in the browser), beans and injection points.
- Go to Declaration into library classes, from Java files and from `application.properties`.

**Java debugging.**

- Values shown at the end of the line while stopped.
- Breakpoints that suspend one thread, remove themselves once hit, or wait for another breakpoint; pass counts.
- Method breakpoints and field watchpoints; Run to Cursor (⌥F9, or a click on a line number); Smart Step Into
  (⇧F7) choosing the call on the line.
- The "Code changed" toolbar that reloads classes during a session, and the Debugger settings pages (Data Views,
  HotSwap, Stepping).

**Kotlin.**

- Debug from the gutter; function breakpoints, and breakpoints on a line's lambdas; coroutine stacks in the frames.
- The Kotlin run configuration's module, JRE and Shorten command line; a subproject's `main` runs in its subproject.
- A banner on Kotlin files in a project without Kotlin, whose Configure adds Kotlin to the Gradle or Maven build.
- Run a Gradle task from its declaration in `build.gradle.kts`.

**Run configurations** you make are now private to your machine until you tick "Store as project file", and keep
their place in the list when you do.

Not yet: signed apps, installers and updates; code coverage; Convert Java to Kotlin and Kotlin's Generate items
(the Kotlin language server doesn't offer them yet); Spring Boot's Beans tool window.

## Opening the unsigned apps

**macOS.** Unzip and move the app to Applications. The first time, macOS refuses to open it: open System Settings ›
Privacy & Security and click Open Anyway beside the app's name, or run
`xattr -dr com.apple.quarantine "/Applications/Spork IDE.app"` (or `/Applications/Spork.app`) in a terminal.

**Windows.** Unzip, then start `Spork IDE\Spork IDE.exe` or `Spork\spork.exe`. When SmartScreen says "Windows
protected your PC", click More info › Run anyway. `Spork IDE\bin\spork-ide.exe` opens folders from a terminal.

**Linux.** Extract into `~/.local`, which puts the apps in `~/.local/bin` and their menu entries in
`~/.local/share/applications`:

```bash
tar -xzf Spork-IDE-v0.1.0-alpha.3-linux-x64.tar.gz --strip-components=1 -C ~/.local
tar -xzf Spork-v0.1.0-alpha.3-linux-x64.tar.gz --strip-components=1 -C ~/.local
```

The apps draw with Vulkan and need its driver, and the Wayland or X11, xkbcommon, fontconfig and ALSA libraries. On
Ubuntu 24.04 or newer:

```bash
sudo apt install git libvulkan1 mesa-vulkan-drivers libxkbcommon-x11-0 libwayland-client0 libx11-xcb1 libfontconfig1 libasound2t64
```
